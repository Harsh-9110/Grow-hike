# API guide

The executable contract is generated by FastAPI at `/openapi.json`; `/docs` lets you try requests. All paths below are relative to the API host. All private endpoints require `Authorization: Bearer ACCESS_TOKEN`, except cookie-based refresh/logout and OAuth callbacks.

Prices, costs, quantities and money in responses are decimal strings. Send decimal inputs as strings. Monetary JSON floats are rejected. Timestamps are timezone-aware ISO strings. Expected failures use `{ "detail": "message" }` or a sanitized validation-error list.

## Authentication

| Method and path | Input / result |
| --- | --- |
| `POST /api/auth/register` | `{ "email":"you@example.com", "password":"a-long-password" }`; creates personal paper portfolio, sets refresh/CSRF cookies, returns access token and user |
| `POST /api/auth/login` | Same body; rate-limited; returns token/user and cookies |
| `POST /api/auth/refresh` | Refresh cookie, matching `X-CSRF-Token` and allowed `Origin`; rotates cookies; returns new access token |
| `POST /api/auth/logout` | Same CSRF/origin checks; revokes session family; clears cookies; 204 |
| `GET /api/auth/me` | Current user ID and email |
| `GET /api/auth/google/start` | Redirects to Google with state, nonce and PKCE |
| `GET /api/auth/google/callback` | Provider callback; verifies identity; sets cookies; redirects to frontend |

An access token expires after ten minutes. Refresh tokens expire seven days after their rotation. Replaying a rotated refresh token revokes its session family. Logout revokes the current session family; it does not claim to sign out all independent devices.

## Market and portfolio

| Method and path | Input / result |
| --- | --- |
| `GET /api/config` | Public demo/integration availability; no production secrets |
| `GET /api/stocks?q=AAPL` | Search the supported catalogue |
| `GET /api/stocks/{symbol}/quote` | Native quote, previous close, currency, provider, fetched/as-of time, stale/demo flags |
| `GET /api/stocks/{symbol}/history` | Daily close series and provider/stale/demo flags |
| `GET /api/fx` | Shared cached USD/INR quote |
| `GET /api/portfolios` | Your portfolio IDs/names/types |
| `GET /api/portfolios/{id}` | Cash, value, native/INR P&L, positions, allocations, XIRR and caveats |
| `GET /api/portfolios/{id}/ledger` | Entries in sequence order |
| `GET /api/portfolios/{id}/performance` | Daily observations and INR benchmark indices; volatility/drawdown |
| `POST /api/portfolios/{id}/orders` | Header `Idempotency-Key: UNIQUE-KEY`; body `{ "symbol":"RELIANCE.NS", "side":"BUY", "quantity":"10" }` |

A successful order returns `{ "entry": { ... }, "replayed": false, "demo": true/false }`. A safe retry returns the same entry with `replayed=true`. The request hash includes canonical symbol, side and normalized quantity; changing the body with the same key returns 409. The UI preserves the key after a timeout or a successful click until the order input changes.

Quotes are fetched before taking the portfolio lock. No API accepts a client-selected execution price. A 409 indicates insufficient funds/shares, stale pricing or a conflicting key. A 404 can mean missing or unowned data. Imported portfolios reject paper orders with 403.

## Watchlists, alerts and streaming

| Method and path | Input / result |
| --- | --- |
| `GET /api/watchlist` | Watched symbols |
| `POST /api/watchlist` | `{ "symbol":"AAPL" }`; adding twice is safe |
| `DELETE /api/watchlist/{symbol}` | Remove a watched stock |
| `GET /api/alerts` | Alert rules and trigger times |
| `POST /api/alerts` | `{ "symbol":"AAPL", "direction":"above", "target":"250" }` |
| `DELETE /api/alerts/{id}` | Remove your rule |
| `GET /api/stream?symbols=AAPL,RELIANCE.NS` | SSE with Authorization header; at most eight symbols and one active stream per user |

The frontend uses `fetch` streaming so the JWT stays in a header rather than a URL. SSE emits a quote batch about once a minute and intervening heartbeats. It stops on expiry, logout or disconnect. It reuses the same quote cache as normal requests.

## Import and broker

| Method and path | Input / result |
| --- | --- |
| `POST /api/imports/preview` | Multipart file plus `mapping` JSON: `{ "symbol":"Ticker", "quantity":"Shares", "average_price":"Avg Price" }`; optional name |
| `POST /api/imports/confirm` | `{ "preview_id":"ID_FROM_PREVIEW" }`; creates read-only portfolio; replay returns same portfolio |
| `POST /api/broker/kite/authorize` | Returns broker login URL and sets browser-bound state cookie |
| `GET /api/broker/kite/callback` | Exchanges provider request token; encrypts access token; redirects to Import |
| `GET /api/broker/kite/status` | Connection availability and expiry note |
| `POST /api/broker/kite/preview` | Reads holdings, then uses the same validation/preview workflow |
| `DELETE /api/broker/kite` | Removes local encrypted token; does not delete past imported snapshots |

Limits: CSV/XLSX only, 2 MB, 500 rows, positive values, known tradable symbols, no duplicate symbol rows. Previews expire after 30 minutes. The body is bounded before multipart parsing. Uploaded file handles are closed; file contents are not retained. Preview row data are stored for confirmation; expired preview records currently remain in the database for administrative cleanup.

Kite imports currently support NSE holdings whose canonical symbols are in the catalogue. Other exchanges must use CSV/XLSX with the exact canonical symbol. The server never calls a broker order API.

## AI, metrics and operations

| Method and path | Input / result |
| --- | --- |
| `GET /api/insights/{symbol}?question=...` | RAG answer or original headlines, source IDs/URLs, fallback/stale note; six requests/user/hour |
| `GET /api/forecasts/{symbol}` | Stored experimental model/baseline evaluation, or honest training-required state |
| `POST /api/ipo/analyze` | `{ "name":"Example IPO", "issue_price":"100", "gmp":"15", "subscription":"3" }` |
| `GET /api/metrics` | Shared cache/provider/status counters, rolling latency statistics and job heartbeat times |
| `GET /health` | Process liveness |
| `GET /ready` | Migrated DB and Redis connectivity; 503 when unavailable |

The IPO endpoint is a manual arithmetic scenario, not a trained listing predictor. The LSTM training command is deliberately offline from HTTP requests. Metrics contain no tokens, account balances or request bodies, but are shared operational statistics visible to signed-in users.
